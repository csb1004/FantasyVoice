# 11 감정 분석기 학습 → 12 감정 피드백 TTS 학습

11에서 **원본 음성 → 감정 확률**을 지도학습합니다. 완료된 모델을 고정한 뒤
12에서 **기존 대사 텍스트 + 감정·운율 라벨 + 캐릭터 ID → 생성 음성**을 학습합니다.
생성 음성을 고정된 분석기에 통과시켜 목표 감정과의 KL 오차를 기존 TTS loss에 더합니다.
12에서 분석기의 가중치는 바뀌지 않으며, 분석기를 통과하는 음성 입력의 미분은 유지합니다.

```text
11: 원본 음성 → 감정 분석기 → 라벨과 비교 → 분석기만 업데이트
12: 대사·라벨·캐릭터 → TTS → 생성 음성 → 고정 분석기 → 라벨과 비교
                         ↑                         │
                         └──── 감정 오차 역전파 ────┘
```

## 실행

최신 `fantasyvoice-pilot.zip`을 `MyDrive/FantasyVoice/`에 덮어씁니다.
새 GPU 런타임에서 `11_train_emotion_analyzer.ipynb`를 실행하고 완료 후
새 런타임에서 `12_train_tts_emotion_feedback.ipynb`를 실행합니다.
11은 데이터 준비 완료 후 실행할 수 있으며, 12는 완료된 09와 11이 모두 필요합니다.

필요한 Drive 경로:

- `MyDrive/Voice/`: 원본 캐릭터 음성
- `MyDrive/FantasyVoice/dataset-prepared-v1.zip`: 기존 train/validation 분할·라벨·대사
- `MyDrive/FantasyVoice/fantasyvoice-pilot.zip`: 최신 실행 코드
- 12에서 추가: `predictor-v1/best-model.pt`, `tts-joint-v1/`의
  `best-model.pt`, `run.json`, `training-report.json`
- 12에서 추가: 11의 `emotion-analyzer-v2-batch/`에 있는 같은 세 파일

11 출력은 `emotion-analyzer-v2-batch`, 12 출력은 `tts-emotion-feedback-v2-batch`입니다.
각 단계의 `latest.pt`는 재개용 모델·optimizer·진행 위치·RNG를 함께 저장합니다.
같은 설정으로 같은 셀을 재실행하면 마지막 저장 경계부터 이어갑니다.
설정/코드/데이터를 변경할 때는 `EXPERIMENT`를 바꾸세요. 원본 모델 폴더와 겹치지 마세요.
한 출력 폴더를 여러 런타임에서 동시에 사용하지 마세요.

기존 08/09의 Drive 증분 캐시를 복원합니다. 음원 캐시는 동일 해시를 재사용하고,
텍스트 캐시는 프런트엔드/라이브러리 버전까지 일치하는 경우 재사용합니다.
11은 텍스트 프런트엔드나 TTS 사전학습 가중치를 로딩하지 않습니다.

## 설정과 메모리

값은 실험 시작용이며 최적화된 설정이 아닙니다.

| 설정 | 11 분석기 | 12 TTS |
|---|---:|---:|
| 실제 배치(T4) | 4 | 4 |
| 실제 배치(L4) | 8 | 8 |
| 누적 횟수 | 1 | 1 |
| epoch | 1 | 1 |
| 학습률 | 1e-6 | 1e-5 |
| 감정 KL 가중치 | 지도학습 목적 | 1.0 |

`BATCH_SIZE='auto'`는 GPU 이름과 실제 메모리를 확인해 T4는 4, L4는 8로 시작합니다.
숫자를 직접 지정할 수도 있습니다. 두 단계 모두 여러 음원을 동시에 처리하는 실제 배치입니다.
각 음원을 따로 정규화한 다음 패딩하고, 분석기의 프레임 마스크로 패딩을 평균에서 제외합니다.
12는 생성 길이별로 패딩을 제거한 음성을 분석기에 전달합니다.
forward/backward에서 CUDA OOM이 발생하면 optimizer 업데이트 전에 해당 묶음 전체를
작은 실제 배치로 다시 계산합니다(8→4→2→1). 이때만 최초 유효 배치를 유지하기 위한
누적이 발생하며 실제 사용 배치를 로그와 체크포인트에 기록합니다.
optimizer 상태 할당 중 OOM이나 한 음원도 들어가지 않는 경우에는 자동 복구하지 않습니다.
현재 값은 실제 T4/L4에서 검증된 최대 배치가 아닌 시작값입니다.
새 기본 EXPERIMENT는 `v2-batch`이며 기존 v1 폴더를 덮어쓰지 않습니다.
이미 완료한 v1 분석기는 12의 `EMOTION_MODEL` 경로를 지정해서 사용할 수 있습니다.
GPU를 바꿔 같은 실행을 재개할 때는 원래 시작 배치 값을 숫자로 지정하세요.

`MAX_SECONDS=15`를 넘는 원본은 이번 실험에서만 제외하고 개수를 보고합니다.
캐릭터가 통째로 제외되면 중단합니다. 로컬 준비 데이터에서는 학습 15개, 검증 1개가
이 조건으로 제외됩니다. 원본/준비 ZIP은 변경하지 않습니다.
생성 길이가 제한을 넘으면 잘라서 평가하지 않고 optimizer 업데이트 전에 중단합니다.

기존 emotion2vec-plus-large의 사용되는 파라미터 전체를 11에서 학습합니다.
12도 전체 생성 음성을 통한 역전파가 필요해 09보다 메모리 부담이 큽니다.
T4/L4 최대 배치는 GPU에서 검증되지 않았습니다. 누적 횟수를 줄이는 것만으로 단일 발화의
메모리는 줄지 않습니다. 더 큰 메모리의 GPU 또는 길이 조건을 검토해야 합니다.
감정 경로는 FP32이며, 기존 TTS GAN 학습의 AMP 설정은 유지됩니다.

## 목적함수와 모델 선택

감정 표의 7개 확률을 soft target으로 그대로 사용합니다.
`KL(목표 감정 || 분석한 감정)`을 계산하며 argmax 정답으로 바꾸지 않습니다.
분석기의 원래 9개 출력에서 기존 데이터 처리와 동일한 7개 클래스를 선택해 정규화합니다.

11은 실제 음성으로만 학습하며 검증 음성을 optimizer에 넣지 않습니다.
학습 전과 매 epoch 전체 검증 KL로 `best-model.pt`를 선택합니다.
**기존 분석표는 사람이 검수한 감정 정답이 아니라 자동 분석한 의사 라벨**입니다.
원래 라벨 생성 모델이 이미 잘 맞추는 경우 초기 모델(update 0)이 최적일 수도 있습니다.
이 경우도 숨기지 않고 보고서에 기록합니다. 재학습이 감정 판단의 정확도를 높였다는
주장은 별도의 청취/라벨 검증 없이는 할 수 없습니다.

12는 기존 재구성·GAN·특징·KL·duration loss에 감정 KL을 추가합니다.
기존 학습의 짧은 재구성 조각이 아니라 **원본 음성을 입력하지 않은 텍스트 기반 전체
생성 음성**으로 감정 loss를 계산합니다. 생성 길이를 정하는 반올림은 미분되지 않으므로
감정 loss가 모든 duration 파라미터까지 전달된다고 주장하지 않습니다.
시작 전에 감정 loss만으로 캐릭터 벡터와 디코더에 유한한 gradient가 도달하는지 검사합니다.

12의 Predictor는 고정되며 학습 입력 조건은 준비 데이터의 실제 라벨입니다.
학습/검증에 새 문장을 만들어 추가하지 않습니다. 보고서의 스타일 변화 청취 샘플도
기존 검증 대사를 사용합니다. 마지막 `predicted-style-preview`만 서비스 추론과 같은
고정 Predictor 경로로 기존 검증 대사 한 개를 생성합니다.

12의 최적 TTS는 기존과 같이 전체 검증 mel로 선택하며, 고정 분석기로 측정한
`generated_emotion_kl`과 `real_emotion_kl`도 기록합니다. 감정 평가는 고정된 검증
부분집합(`EMOTION_VALIDATION_SAMPLES`)을 사용합니다. 이 모델이 학습 loss에도
쓰이므로 감정 점수 향상만으로 청취 품질·화자 유사도 개선을 확정하지 않습니다.
